# Email System

Replaces R **blastula** + DuckDB `email_schedules` + background R scheduler.

---

## Capabilities

1. **Send Now** — immediate report email to recipient
2. **Schedule** — daily, weekly, monthly, or one-time
3. **Manage schedules** — list, activate/deactivate, delete
4. **Background processing** — cron checks due schedules every 15 minutes

---

## Database schema

See `email_schedules` table in `database/001_schema.sql`.

### Key fields
| Field | Purpose |
|-------|---------|
| frequency | daily, weekly, monthly, once |
| send_time | TIME e.g. 09:00:00 |
| day_of_week | 1=Monday (weekly) |
| day_of_month | 1-31 (monthly) |
| send_date | DATE (once) |
| next_send_at | Precomputed TIMESTAMPTZ for cron query |
| report_filters | JSONB — filter state + chart options |
| report_charts | TEXT[] — sections to include |
| last_sent | Last successful send timestamp |

## Computing `next_send_at`

Timezone: **Australia/Sydney**

```python
from zoneinfo import ZoneInfo
from datetime import datetime, time, timedelta

TZ = ZoneInfo("Australia/Sydney")

def compute_next_send(schedule) -> datetime:
    now = datetime.now(TZ)
    send_time = schedule.send_time  # time object
    
    if schedule.frequency == "daily":
        candidate = datetime.combine(now.date(), send_time, TZ)
        if candidate <= now:
            candidate += timedelta(days=1)
        return candidate
    
    elif schedule.frequency == "weekly":
        # day_of_week: 1=Mon ... 7=Sun
        days_ahead = (schedule.day_of_week - now.isoweekday()) % 7
        candidate = datetime.combine(now.date(), send_time, TZ) + timedelta(days=days_ahead)
        if candidate <= now:
            candidate += timedelta(days=7)
        return candidate
    
    elif schedule.frequency == "monthly":
        # day_of_month on current or next month
        ...
    
    elif schedule.frequency == "once":
        return datetime.combine(schedule.send_date, send_time, TZ)
```

Store result in `next_send_at` on create/update. After send, recompute next.

## Email content

### Subject
Default: `Automated Livestock Report - {farm_name} - {date}`  
Override: `email_subject` field

### Body (HTML)
```html
<p>Hello,</p>
<p>Please find your automated livestock performance report attached.</p>
<p><strong>Filters applied:</strong></p>
<ul>
  <li>Year: 2024</li>
  <li>Measure: Final processed weight</li>
  ...
</ul>
<p>{custom email_body}</p>
```

### Attachments
1. **Report PDF** (or HTML) — generated by `report_generator.py`
2. Optional: chart PNGs embedded or attached

## Report generation (port from `report_generator.R`)

### `generate_summary_stats(filtered_data, measure)`
Returns dict with mean, median, min, max, std, count.

### `generate_filter_summary(filters)`
Human-readable filter dict for email body.

### `create_dashboard_chart(filtered_data, chart_type, measure, grouped_data)`
Returns path to temp PNG:
- **Distribution** — histogram
- **Time Series** — daily mean line chart
- **Summary** — text table image or skip

Use **matplotlib** or **plotly + kaleido** for PNG export.

### `generate_report_pdf(filters, charts, farm_name)`
Use **WeasyPrint**, **reportlab**, or **jinja2 + pdfkit**:
- Cover: farm name, date, filter summary
- Sections per selected chart
- Summary statistics table

Formats:
- `PDF` — direct PDF download
- `HTML` / `PRINT_HTML` — HTML optimized for print/PDF conversion

## Background scheduler

### Option A: Vercel Cron (if API on Vercel serverless)
`vercel.json`:
```json
{
  "crons": [{
    "path": "/api/email/process-due",
    "schedule": "*/15 * * * *"
  }]
}
```

Protect with `X-Cron-Secret` header matching env var.

### Option B: Render/Fly cron job
```bash
*/15 * * * * curl -X POST https://api.example.com/api/email/process-due -H "X-Cron-Secret: $SECRET"
```

### Option C: Supabase pg_cron + Edge Function

### `process_due_emails()` algorithm
```python
def process_due_emails():
    due = db.query("""
        SELECT * FROM email_schedules
        WHERE is_active = TRUE
          AND next_send_at <= NOW()
    """)
    for schedule in due:
        try:
            filters = schedule.report_filters
            report = generate_report_pdf(filters, schedule.report_charts, ...)
            send_email(schedule, report)
            db.update(schedule.id, last_sent=now(), next_send_at=compute_next(schedule))
        except Exception as e:
            log.error(f"Failed schedule {schedule.id}: {e}")
```

## Reports page UI wiring

### Send Now flow
1. User fills recipient + optional subject/body
2. Current sidebar filters captured as `report_filters`
3. `POST /api/email/send-now`
4. Toast: "Email sent successfully" or error

### Schedule flow
1. User selects frequency, time, day options
2. `POST /api/email/schedules`
3. Refresh schedules table

### Schedules table columns
| Column | Content |
|--------|---------|
| ID | schedule.id |
| Recipient | email |
| Frequency | daily/weekly/... |
| Time | HH:MM |
| Active | toggle |
| Last Sent | timestamp or "Never" |
| Actions | Delete |

## Error handling

| Error | User message |
|-------|--------------|
| Invalid email | "Please enter a valid email address" |
| SMTP failure | "Failed to send email. Try again later." |
| No data for filters | "No data matches current filters for report" |
| Missing report_filters | "Schedule saved but filters were empty" |

Log full errors server-side; never expose SMTP credentials.
